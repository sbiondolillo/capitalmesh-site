# Minutes source files are gitignored, never committed

Minutes contain internal, members-only content — attendance, financial line items, action items
— and are generated by tooling that lives in this repo (`capitalmesh-site`). That repo is public on
GitHub and deploys to GitHub Pages. We decided Minutes source files are written to a
`.gitignore`d local directory inside the repo (e.g. `.claude/skills/new-event-post/.minutes/`) and
are never committed.

The non-obvious risk this avoids: excluding a directory from Hugo's build (e.g. via `_build:
{render: never}` or keeping it outside `content/`) stops it from being *published* on the live site,
but does nothing to stop it being *committed* — anything pushed to this repo is visible in public
git history regardless of whether Hugo ever renders it. A `.gitignore` entry is the only thing in this
setup that actually keeps member financial and attendance records out of a public history.

This is hard to reverse in the sense that matters: if a minutes file is ever committed by mistake, it
is in public git history permanently (or requires history rewriting to remove). Colocating the tool
with the site repo was chosen for convenience over standing up a second private repo; that
trade-off is worth revisiting if minutes-handling ever needs stronger guarantees than "we
configured `.gitignore` correctly."
